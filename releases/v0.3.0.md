# v0.3.0 — Ultra-simple: PROFILE-only, all skills retired

`gsd-mentor` v0.3.0 is the bold cut. **PROFILE.md is the only memory surface.** All wiki/ (concepts, bridges, exercises, synthesis, index.md, log.md), all session transcripts (raw/sessions/), and all four skills (mentor-ingest, mentor-query, mentor-lint, mentor-bridge) are archived. The agent rewires onboarding to ripgrep-first (never full-read PROFILE) and updates PROFILE.md inline during conversation — no ingest ceremony, no slash commands, no confirmation gates.

## TL;DR

v0.2.0 retired `wiki/concepts/`. v0.3.0 retires everything else. The wager is simple: the model already knows coding from training; what it needs from persistent storage is **who Ken specifically is** — his exact phrasings, Python anchors, confirmed gaps, senior-track habits, mentoring preferences. PROFILE.md carries that. Everything else was comfort-blanket curation. ~30× reduction in per-session write cost. Mentoring philosophy (Socratic, Density, Anti-leak, Momentum mode) preserved verbatim.

## Why this release exists

The first session under v0.2.0 (Mixed Juices, a JavaScript Exercism exercise on `while` loops + `switch`) closed with the v0.2.0 ingest protocol — and produced ~19K tokens of writing across six files: a `PROFILE.md` session-log entry, an `index.md` catalog update, a new `wiki/bridges/python-vs-js-call-by-sharing.md`, a `wiki/exercises/mixed-juices.md`, a `raw/sessions/2026-05-15-mixed-juices.md`, and a `wiki/log.md` append.

The user's retro question, verbatim:

> *"did the skill make it clear that i dont ever read wiki and every docs in gsd-mentor is just for your running references? ... because all those in the wiki you wrote with details I would argue dont need to write that at all and the brideges etc I NEVER READ IT. why bother? and the session logs i dont read it. When i spawn you fresh what exactly would you read first? afraid we regression here. i would say we only need to maintain the profile.md then you use ripgrep to understand the main points to onboard with minimal token as possible cause you as a model already knows all about coding."*

Direct and unambiguous: cut to PROFILE-only.

The mentor agent audited its own ingest and conceded the comfort-blanket diagnosis. Of the ~19K tokens written:

| File | Tokens | Earned its keep? |
|---|---|---|
| `PROFILE.md` session-log h4 entry (quotes + analogies) | ~3K | ✅ Primary recall — echo-back currency |
| `wiki/index.md` catalog entries | ~0.3K | ✅ Cheap + scanned every session start |
| `wiki/bridges/python-vs-js-call-by-sharing.md` | ~5K | ⚠️ Novel layer, but PROFILE quotes cover the same recall |
| `wiki/log.md` chronological entry | ~0.4K | ⚠️ Covered by PROFILE session-log dates |
| `raw/sessions/{date}.md` | ~6K | ❌ Duplicates PROFILE session log |
| `wiki/exercises/{name}.md` | ~4K | ❌ Solution sketch lives in exercise repo; "what was learned" duplicates PROFILE |

The mentor's own admission: half the bytes were re-writing what the model already knew, the other half were re-writing what PROFILE already captured. Same shape as the v0.2.0 retirement of `wiki/concepts/`, one layer deeper.

The user then went further: **retire all of it.** Including skills. The agent can update PROFILE inline during conversation; no separate ingest skill is needed. Cross-language anchoring can happen mid-turn without a bridges/ file as scaffolding.

v0.3.0 is the bold cut.

## What v0.3.0 is BETTING on

The wager: the model's training data already contains every programming concept Ken will encounter via Exercism, and the marginal value of curated wiki files is near-zero compared to a sharp PROFILE.md that tells the model **who Ken specifically is**. Verbatim quotes + analogies + gaps + strengths are non-substitutable; the rest is comfort blanket.

If the wager is wrong — if Python↔JS cross-language anchoring degrades because the `wiki/bridges/` files are gone — the failure mode is observable in 2-3 sessions (mentor stops surfacing cross-language framings unprompted). Recovery is folding the highest-leverage bridge quotes into PROFILE strengths as permanent hooks.

`_archive/v3-2026-05-15/` holds every retired file verbatim. Reversal is `mv` — but before reversing, name the specific recall task v3 failed at. If no concrete failure, the comfort-blanket pull is just nostalgia.

## Vision (unchanged from v0.2.0, applied harder)

> **gsd-mentor is your partner for the daily 1h. Job: keep the hour generative — you type your reasoning, the mentor reflects it back tightened, sparks form. Remember what stuck so today's drill builds on yesterday's. Nothing outside the hour.**

v0.2.0 narrowed the *scope*. v0.3.0 narrows the *surface area* to match. Same vision, lighter footprint.

## Breaking changes

**This is a breaking release for anyone who was running v0.2.0** and relying on:

- The four mentor skills (`/mentor-ingest`, `/mentor-query`, `/mentor-lint`, `/mentor-bridge`) — all gone. The agent no longer invokes them. If you had them mapped to natural-language triggers, those triggers now route to inline PROFILE updates instead.
- The `wiki/` directory as a write target — agent no longer writes there. Existing `wiki/` content in v0.2.0 installations is preserved as-is; no migration script needed, just stop expecting new content to appear.
- The `raw/sessions/*.md` per-session captures — no longer produced. PROFILE session-log h4 entries are the source of truth.

## Migration notes (v0.2.0 → v0.3.0)

1. **Update your agent file.** Copy the new `.claude/agents/gsd-mentor.md` from this release (or pull the repo). Mentoring philosophy is identical; only the wiki/skills/onboarding sections changed.
2. **Update `CLAUDE.md`.** New v3 schema slims to ~80 lines from ~130. Points at PROFILE.md as single source of truth.
3. **Archive your existing wiki/ and raw/sessions/** (optional). The agent simply won't touch them anymore — leaving them in place is fine. If you want a clean tree, move them to `_archive/v3-YYYY-MM-DD/`.
4. **Update `.gitignore`.** Retired surfaces no longer need per-file entries. Add `_archive/` to ignore the archive bundle. New gitignore is in this release.
5. **Stop running `/mentor-ingest`.** It doesn't exist anymore. The agent updates PROFILE.md inline during conversation, weaving captures into the closing acknowledgment of each session.
