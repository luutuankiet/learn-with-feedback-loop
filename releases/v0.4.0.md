# v0.4.0 — Agent retired: two portable skills + a forever-profile

`gsd-mentor` stops being an *agent*. v0.4.0 splits the mentoring system into two **Claude Code skills** and migrates the learner profile to a 3-tier schema built to grow indefinitely.

## TL;DR

- The always-on `gsd-mentor` agent is **retired**. Its teaching discipline now lives in a portable, filesystem-blind skill: **`learn-with-reps`**.
- A second skill, **`learn-with-reps-gsd`**, is an optional **sidecar** that adds the persistent learner-profile (ripgrep-in at session start, distill-out at wrap). It auto-loads alongside the generic skill when a filesystem is reachable.
- `PROFILE.md` moves from a single-track, append-only structure to a **3-tier, multi-track schema** (Learner Core / Topic Ledger / Session Log) where the header text encodes learner state — so `rg '^### \['` returns your whole learning map in one shot, and the file stays ripgrep-fast as it grows forever.
- The teaching philosophy is unchanged and sharpened: a 3-part success metric (you succeed only when the learner *writes*), multi-topic turns, assume-don't-interview onboarding, psychological safety, and a per-turn navigation recap.

## Why this release exists

v0.3.0 already cut the system to a single agent + a single `PROFILE.md`. Two things pushed it further:

1. **The discipline is bigger than this repo.** The Socratic, write-to-think mentoring is valuable in *any* session, with *any* agent — even pasted into a bare chat with no files. Trapping it inside one project's agent definition wasted it. So the discipline became a self-contained, filesystem-blind skill, and everything project-specific (the profile, the file paths) moved into a separate sidecar that only loads when it can reach a filesystem.
2. **The profile needed to outlive one language.** The old profile was effectively single-track, and its section headers were opaque — you couldn't tell from an outline whether a concept was a gap, in progress, or owned. The new schema encodes that state directly in each header and partitions by learning track, so one `rg` is the whole picture, and a rollup valve keeps the outline bounded no matter how many months accumulate.

## Breaking changes

**This breaks anyone running v0.3.0 (the single agent):**

- **The `gsd-mentor` agent is gone.** `.claude/agents/gsd-mentor.md` is removed from the repo — there is no more `claude --agent gsd-mentor`. Install the two skills instead (see the README).
- **Install path changed.** Skills now ship under `skills/` at the repo root (not `.claude/`). Copy them into your project's `.claude/skills/`.
- **`PROFILE.md` structure changed.** The flat v3 sections become three tiers. The sidecar's `ref/profile-schema.md` documents the new shape; `PROFILE.template.md` is the new seed. Existing profiles keep working as free text, but to get the one-grep map, migrate to the tiered header grammar.

## Migration (v0.3.0 → v0.4.0)

1. **Remove the agent.** Delete your old `.claude/agents/gsd-mentor.md`; stop using `--agent gsd-mentor`.
2. **Install the skills.** `cp -r skills/learn-with-reps skills/learn-with-reps-gsd ~/yourproject/.claude/skills/`.
3. **Point the sidecar at your profile.** Edit the example path in `learn-with-reps-gsd/SKILL.md` to your `PROFILE.md` location.
4. **(Optional) migrate your profile** to the 3-tier schema using `ref/profile-schema.md` as the spec — or start fresh from `PROFILE.template.md` and let the sidecar fill it in.
5. **Just talk.** No slash commands. Describe what you're learning; the generic skill mentors, the sidecar remembers.
