# v0.6.0 — `rebuild-to-own`: turn a codebase you never wrote into a graded curriculum

Minor release: a third skill joins the family. `learn-with-reps` proves you can *explain* something; `rebuild-to-own` proves you can *produce* it.

## TL;DR

- **New skill `rebuild-to-own`.** Point it at a repo you approved specs for but never implemented. It authors an exercism-style track over that repo: one branch per topic, each scaffolded down to signatures + contract-comments (+ failing tests where the logic is pure), and grades your commit against the shipped implementation. Three modes: **TAILOR** (survey the code, propose the menu, plant the seeds - never teaches), **TEACH** (scaffold one topic and deliver the lesson), **GRADE** (review your commit).
- **The core trick: git supplies all three ingredients for free.** `git worktree add --orphan` gives a genuinely empty working dir; the scaffold commit gives the spec; and because plain `git diff` is tree-vs-tree, `git diff <default-branch>` and `git show <default-branch>:<file>` work *across unrelated histories* — so the finished code in the same repo is the answer key. No fixture copies, no separate solution repo, no network.
- **First-principles teaching is mandatory here, not optional.** Each topic is taught problem-that-existed-first → origin/history → the design pressures that produced *this* shape → how it wires to its neighbors → the surviving trade-off — all *before* the stub is shown. A learner shown the stub first optimizes for filling the stub; a learner shown the pressure first can re-derive it.
- **Grading is a diff read, not a code read.** A codified ladder — `log` → `--stat` → per-file diff → convergence diff vs the reference → targeted grep only when a hunk is ambiguous → full read as a last resort with a stated reason. Budget: ~3 git commands and at most one grep per graded topic.
- **The `learn/` docs ship as templates.** `skills/rebuild-to-own/templates/` carries skeletons for `CHARTER.md`, `MAP.md`, `LEDGER.md` and a topic brief, plus a `pilots.md` seed. They exist because the boot greps are a contract, not a convention: sessions find topics with `rg '^### \['`, section menus with `rg '^## '`, and staleness with `synced-at:` — a doc whose headings were phrased differently returns *nothing* and the session silently falls back to reading whole files. Content is per-repo; structure is not.
- **The profile is now found by rule, not by a configured path.** The sidecar resolves `PROFILE.md` at the root of whichever project's `.claude/skills/` loaded it, then any path pinned by a project or a rebuild track's `CHARTER.md`, then asks. Installing no longer means hand-editing a path into the skill.
- **`DESIGN.md` ships alongside the skill** — artifact graph, the three modes as flow diagrams, nine decisions with their rejected alternatives, and the invariants. `SKILL.md` runs a session; `DESIGN.md` is for changing the rig.

## Why this release exists

Agent-built codebases create a specific debt: you approved the specs, discussed the architecture, reviewed the PRs — and cannot produce a line of it. Comprehension mentoring treats the symptom (you can narrate the code and still not write it). Generic katas miss on relevance (they don't build the system you're actually on the hook for). What was missing is exercism's *format* pointed at *your* repo.

The blocker had always been the answer key: a rebuild curriculum needs a blank slate, a spec, and a reference to grade against, and maintaining those by hand is more work than the learning. Verifying that orphan worktrees diff cleanly against an unrelated history removed that blocker entirely — the repo already contains all three.

## Design notes worth knowing

- **Docs live on one `learn/syllabus` branch; exercise branches carry code only.** Doc files on an exercise branch pollute the graded diff and drift from the central copy. Each exercise branch's seed is its *scaffold commit message* plus contract-comments in the stubs — metadata, so it never appears in a diff.
- **Status lives in header text**, so `rg '^### \['` is equivalent to reading the whole topic map — the same trick the learner profile uses. Every doc opens with a `## Menu` table so both consumers (a planning agent and a session agent) enter through the same minimal-token index.
- **Local-only by default.** The target repo is usually a *collaborator's*. The skill forbids commits to its default branch outright and requires explicit per-repo consent before pushing any `learn/*` branch. Everything works offline — the answer key reads the local object store.

**One behaviour change worth reading if you already run the sidecar.** `learn-with-reps-gsd` no longer carries a hard-coded profile path. On upgrade it will look for `PROFILE.md` at the root of the project that loaded it; if yours lives elsewhere, pin the path in that project's instructions rather than editing the skill — skills are now expected to be symlinked, and a local edit to a symlinked skill is an edit to the shared copy. `learn-with-reps` itself is untouched.
